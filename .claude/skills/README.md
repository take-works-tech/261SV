copy in place, which would be a fork nobody records.

## Considered and rejected (recorded so nothing is re-proposed)

Thirty-five further candidates from four catalogues (Qiita, aitmpl.com, note/gadgelog, and a sweep of
all 19 skills in anthropics/skills) were evaluated on 2026-08-29 and rejected. Five classes cover
them, so a future candidate can be triaged in one line:

1. **External palette/theme/token sources** - theme-factory, brand-guidelines, ui-design-system,
   tailwind-design-system, baseline-ui, shadcn, UI/UX Pro Max. The token system is decided (XC-187)
   and single-authored; a second opinion source is the `--muted` incident waiting to recur.
2. **Redundant accessibility auditors** - AccessLint, fixing-accessibility, accessibility-auditor.
   Authoring-time rules are in web-design-guidelines; verification is the planned @axe-core/playwright
   gate.
3. **Verification outside the wired gates** - design-review, Playwright MCP, webapp-testing. Checks
   live in validate/ and CI (`check_gates_wired.py`); an ad-hoc review skill produces evidence outside
   that system.
4. **Wrong platform, deployment model or surface** - mobile-design, progressive-web-app, scroll
   experiences, canvas/algorithmic art, portfolio/SEO/video/slides, Figma (no Figma in this workflow,
   and its MCP is a network dependency in an offline product), web-artifacts-builder (the deliverable
   is generated by the engine under spec invariants, not scaffolded).
5. **Unverifiable provenance or duplicated project process** - ux-strategist,
   design-requirements-grill, premium-web-design, taste-skill, apple-design.

Two carry explicit revisit conditions: **tailwind-patterns**, if Tailwind-4-specific mistakes recur in
practice (the mockup really is Tailwind 4); and **claude-d3js-skill**, if d3 is chosen as the
deliverable's graph renderer. The one capability gap that may eventually need a skill is
**deliverable-graph design**, to be filled when the renderer is decided - by extending `solvia-ui` or
authoring a project chart-rules skill, not by installing a generic one.

## Order of authority

`solvia-ui` binds the generic skills to this product: tokens only, seven states, instrument-screen
rules, and an explicit adopt/reject map for `frontend-design`'s editorial advice. On any UI work,
load `solvia-ui` first (the plugin-delivered `frontend-design` included). Where skills disagree, solvia-ui wins; where solvia-ui and the specs
disagree, the specs win - and say which, rather than proceeding (AGENTS.md).

These are development-time tools. Nothing here ships in the product, so XC-025's attribution file
does not list them; this README is their licence record instead.
