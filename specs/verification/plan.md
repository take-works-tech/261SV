# Verification plan

How each acceptance criterion is checked: by what test, with what data, to what tolerance.

No code exists yet, so automated rows are written as `(planned)`: the intent is recorded now, and the
row starts demanding a real, existing test the moment the word `planned` is removed. That removal is
the moment the criterion begins claiming coverage.

**Fixture data is named here and its origin recorded.** A tolerance measured against a sample of
unknown origin proves nothing, and months later nobody can tell whether it was representative.

Fixtures are generated by the test code itself wherever the toolkit can write the format - EnSight,
Exodus, IOSS, VTKHDF, VTK XML including partitioned files, STL - so they carry no third-party terms
(XC-085). CGNS and the Offered-tier formats cannot be written, so those rows are marked manual and
name a locally held file rather than a committed one. **A generated fixture only contains the problems
we thought of**, which is why the manual rows exist rather than being quietly dropped.
